# SentinelOS

Autonomous multi-agent AI security engineering platform. Point it at a GitHub
repo (or a zip), and it runs real static-analysis scanners, then hands the
findings to six role-based agents that explain, simulate exploitation of,
patch, score, and report on them — live, on a dashboard.

## Architecture

```
repo/zip -> Scanner Agent (Semgrep, Bandit, npm audit, pip-audit; no LLM)
         -> Threat Analysis Agent      (CrewAI, per finding)
         -> Attack Simulation Agent    (CrewAI, high-signal findings -> attack graph)
         -> Patch Generation Agent     (CrewAI, per finding -> unified diff)
         -> Risk Assessment Agent      (CrewAI, per finding -> composite score + rank)
         -> Report Agent               (CrewAI -> executive summary; PDF via WeasyPrint)
```

Progress — including real Semgrep/Bandit/npm-audit/pip-audit subprocess
output and each agent's per-finding activity — streams to the frontend over
SSE (`/api/scan/{id}/stream`) as `agent` and `log` events, driving a
"digital command center" dashboard:

- **`/overview`** — aggregate stats and recent activity across every scan
- **`/scan`** — target selection (repo URL or `.zip`/`.tar.gz` upload) and
  live scan progress with a real streaming terminal log panel
- **`/agents`** — the vulnerability feed with per-finding threat analysis,
  expandable in place
- **`/patches`** — before/after diff viewer for generated patches
- **`/reports`** — PDF download per scan

A 4-step Stepper (Scan → Threat Analysis → Attack Simulation → Patch
Generation) tracks live pipeline progress across those pages; Risk
Assessment and Report still run and feed stat cards and the PDF, they just
don't get their own stepper node. Attack-chain and executive-summary data
are generated by the backend as before but aren't surfaced in this UI —
only the PDF report includes them.

**LLM fallback chain**: every agent tries a CrewAI Agent backed by OpenAI
first, falls back to Gemini if only `GEMINI_API_KEY` is set, and — if neither
key is configured or a call fails — falls back to a deterministic heuristic
built from the finding's own fields. This means the full six-agent pipeline
always completes end-to-end, even with no API key at all; it just produces
templated rather than model-written analysis/patches/narrative.

## Prerequisites

- Python 3.11+
- Node.js 18+
- Semgrep, Bandit, pip-audit, and npm on `PATH` (the scanners shell out to
  them as subprocesses — they are intentionally **not** installed via
  `backend/requirements.txt`, see the comment at the bottom of that file for
  why, particularly on Windows)

## Backend

```bash
cd backend
python -m venv .venv
./.venv/Scripts/activate        # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install semgrep bandit pip-audit   # see requirements.txt comment
cp ../.env.example .env         # then fill in OPENAI_API_KEY / GEMINI_API_KEY
uvicorn main:app --reload --port 8000
```

Health check: `GET http://localhost:8000/health`. Interactive API docs at
`/docs`.

### PDF export on Windows

WeasyPrint needs native Pango/Cairo/GDK-Pixbuf libraries. They install
cleanly on Linux (Railway/Render build steps just need
`apt-get install libpango-1.0-0 libpangocairo-1.0-0 libgdk-pixbuf2.0-0
libffi-dev`) and on macOS (`brew install pango`), but are not present on a
bare Windows machine. Until installed, `GET /api/scan/{id}/report` returns a
`503` with a clear message instead of crashing — every other feature
(including the on-screen Executive Summary) works normally.

## Frontend

```bash
cd frontend
npm install
cp .env.local.example .env.local   # set NEXT_PUBLIC_API_URL if not localhost:8000
npm run dev
```

Open `http://localhost:3000`.

## Trying it end-to-end

A small deliberately-vulnerable fixture lives at `sample-vulnerable-repo/`
(and pre-zipped as `sample-repo.zip`) — SQL injection, command injection,
unsafe deserialization, a hardcoded secret, and outdated Python/JS
dependencies. Drop `sample-repo.zip` onto the `/scan` page's upload zone to
see the whole pipeline run without needing a real GitHub URL.

## Environment variables

See `.env.example` at the repo root. `OPENAI_API_KEY` / `GEMINI_API_KEY` are
optional (see LLM fallback chain above); everything else has a sane default
for local development.

## Deployment

- **Frontend**: Vercel. Set `NEXT_PUBLIC_API_URL` to the deployed backend URL.
- **Backend**: Railway or Render. The build step must install Semgrep,
  Bandit, pip-audit, and Node/npm (for `npm audit`) in addition to
  `pip install -r requirements.txt` and WeasyPrint's native libs (see above).
